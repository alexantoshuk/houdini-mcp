# Skills security review

Date: 2026-11-02  
Scope: `.cursor/skills/houdini-*/SKILL.md` + `skills/vendor/fxhoudinimcp/`

## Verdict

**No malware / prompt-injection / secret-exfiltration content found** in the imported guides.

They are technical Houdini workflow docs (MIT, from [fxhoudinimcp](https://github.com/healkeiser/fxhoudinimcp)). Residual risk is **capability amplification** when an agent combines the skills with the live `houdini-mcp` bridge.

## Real risks (operational)

1. **`execute_python` in our MCP bridge** runs arbitrary Python inside Houdini (`exec`). Skills discourage it, but still mention it. This is the highest privilege surface.
2. **TOPs / farm guidance** (`houdini-tops`, discipline node lists: Tractor, `sendcommand`, `pythonprocessor`) can push an agent toward expensive or remote cooks if the user is unclear.
3. **Disk writes** (file cache, render, save/load hip) can overwrite project data; skills encourage caching (good for FX, risky without confirm).
4. **Shelf tools** (`run_shelf_tool`) — upstream pattern; not implemented in our MCP today, but if added later it can run SideFX Python recipes with side effects.
5. **Supply chain**: skills track a third-party repo. Re-import only from a pinned commit/tag and re-scan (`python scripts/scan_skills_security.py`).

## Mitigations in place

- Each skill includes a **Security guardrails** section (regenerated by `scripts/import_fxhoudini_skills.py`).
- Bridge refuses deleting protected roots (`/obj`, `/stage`, …).
- Zed / Cursor tool approval still applies to MCP tool calls.

## Recommended next hardenings (optional)

- Sandbox or deny-list `execute_python` (block `import os/subprocess/socket`, restrict builtins).
- Require explicit user confirmation env flag for save/load/cache/render.
- Keep farm schedulers out of default agent profiles.
